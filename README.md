# Сварка · Практикум

Готовое автономное PWA на русском языке. HTML, CSS и JavaScript, без сборки, регистрации, рекламы, CDN и серверной базы данных.

## Возможности

- 800 заданий: 480 теоретических/ситуационных и 320 расчётных вариантов по 16 формулам.
- Ровно 20 вопросов в тесте: 12 теоретических/ситуационных и 8 расчётных. Варианты ответов перемешиваются.
- Правильный ответ и объяснение показываются сразу после любого выбора.
- После теста — разбор ошибок, просмотр всех ответов и кнопка следующих 20 вопросов.
- 40 тестов в одном круге. Идентификаторы вопросов не повторяются до завершения всех 800; следующий круг перемешивается заново. Темы и проверяемые принципы могут повторяться в разных формулировках.
- Автосохранение после ответа; продолжение незавершённого теста; статистика; экспорт и импорт резервной копии JSON.
- Service Worker сохраняет приложение и всю базу для офлайн-работы. Новая версия устанавливается после подтверждения.

## Установка через GitHub Pages

1. Распакуйте архив. Создайте в своём GitHub репозиторий, например `welding-practice`. Для бесплатного GitHub Pages обычно используется публичный репозиторий: его исходные файлы будут видны другим. Личные ответы туда не отправляются.
2. Загрузите **содержимое** папки проекта в корень репозитория. В корне должны лежать `index.html`, `app.js`, `engine.js`, `questions.js`, `style.css`, `sw.js`, `manifest.webmanifest`, папка `icons`. Загружать ZIP вместо файлов нельзя. Остальные файлы нужны для документации и проверки, их тоже можно загрузить.
3. Откройте **Settings → Pages → Build and deployment → Deploy from a branch**. Выберите ветку **main**, папку **/(root)**, затем **Save**.
4. Дождитесь завершения публикации. Откройте HTTPS-адрес, который покажет GitHub Pages. При открытии сайта проекта сохраняйте завершающий `/` в адресе папки.
5. Дождитесь надписи **«Офлайн готов ✓»**. Первая загрузка требует интернета.
6. **Android:** откройте адрес в Chrome, меню → «Установить приложение» или «Добавить на главный экран» (названия зависят от версии браузера).
7. **iPhone/iPad:** откройте адрес в Safari, «Поделиться» → «На экран “Домой”»; если предлагается переключатель открытия как веб-приложения, включите его. Запустите установленный значок и дождитесь готовности офлайн-кэша.
8. Проверьте в авиарежиме: откройте приложение, ответьте, закройте и откройте снова. Сохранённый ответ должен остаться.

Прямое открытие `index.html` как локального файла не устанавливает PWA. Для Service Worker нужен HTTPS или localhost. Приложение поставляется несколькими локальными файлами: это необходимо для обычной установки Service Worker, манифеста и значков. После кэширования сетевые библиотеки ему не нужны.

Репозиторий и публичный сайт автоматически не создавались. Архив полностью готов к загрузке.

## Сохранение прогресса

Прогресс хранится на устройстве для конкретного адреса сайта. Он не синхронизируется между телефонами автоматически. В разделе «Прогресс» регулярно сохраняйте резервную копию JSON. Её можно импортировать на другом устройстве; импорт заменяет текущий прогресс после подтверждения.

Очистка данных браузера, удаление веб-приложения, приватный режим, ограничения места и смена адреса могут повлиять на сохранение. Запрос постоянного хранения — дополнительная мера, а не гарантия. Перед переносом и обновлениями сохраняйте копию. На iOS данные вкладки Safari и установленного приложения могут отличаться; переносите их через экспорт/импорт.

Кэш загружается фоновым Service Worker при установке версии. Это **не постоянно работающая фоновая служба**: система может остановить её, особенно на iOS. Для тестирования офлайн это не мешает. Поиск новой версии выполняется при открытии/возвращении в приложение с интернетом. Без интернета продолжает работать установленная версия.

## Содержание и достоверность

Смотрите `SOURCE_REVIEW.md`. У каждого задания есть объяснение и источник/формула. База авторская учебная, не официальный экзаменационный банк. Расчётные варианты честно выделены отдельно; это не 800 различных тем. Дата редакционной проверки: 16.11.2026. Проверка не является независимой профессиональной аттестацией.

## Проверка и доработка

Python 3 и Node.js нужны только разработчику, пользователю телефона они не нужны.

```sh
python3 build_bank.py
python3 tests/test-bank.py
node tests/test-engine.cjs
node tests/test-sw.cjs
python3 -m http.server 8080
```

Затем откройте `http://localhost:8080/`. Для публикации не нужна команда сборки: готовый `questions.js` уже включён.

При изменении файлов приложения меняйте версию кэша в `sw.js`, иначе старый кэш продолжит обслуживать установленное приложение. Все обязательные файлы должны оставаться в списке предварительного кэширования. Перед публикацией проверяйте обновление поверх существующего прогресса. Не меняйте смысл существующего ID и номера вариантов ответа: иначе старые ответы будут интерпретированы по новой редакции. Для изменения состава/смысла базы требуется продуманная миграция состояния и версия базы в `engine.js`.

## Файлы

`index.html`, `style.css`, `app.js` — интерфейс; `engine.js` — очередь и проверка состояния; `questions.js` — офлайн-база; `sw.js` — кэш; `manifest.webmanifest`, `icons/` — установка; `data/theory.txt`, `build_bank.py` — редактируемые исходники; `data/questions.json` — база в читаемом виде; `tests/` — проверки. Результаты проверки: `TEST_REPORT.md`.
